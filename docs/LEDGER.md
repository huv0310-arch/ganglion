# 判决账本 · The Ledger (V2 变体规范)

> **V1 是尺子，V2 是账。**
> 尺子量过的每一次，都留一节。
>
> 本文**不含任何测试数字**。你的负载、你的判据、你的账，跟我们的不一样——
> 量出来的才算你的。第 7 节给方法，第 8 节说为什么。
>
> 本文也**不替你定任何参数**。第 10 节把「什么不许动」和「什么必须你自己填」分开列清：
> 前者是尺子，后者是你的账。**一个默认值都不给**——给了，你抄一遍就能跑，
> 跑出来的是别人的判断，不是你的。

## -1. 什么时候该用它（先看这页，别急着读论文）

**一个特征就够判断**：同一件事会不会被反复问，而且每次答案都该一样？

- **是** → 装。你省下的是"重复判"的那一遍，赚到的是"事后能说清为什么"。
- **不一定** → 先别装。等你能说出"这一句、这一格、这一票"到底是哪一件具体的事，再回来。
- **不是**（一次性、答案随时变、不需要留痕）→ 别装。这不是缓存中间件，也不是数据库。

具体到手上的活，常见就是这八种：

| 你手上在干的事 | 账本替你记住 | 典型的翻面 |
|---|---|---|
| AI 前门：这句话该拦还是该放 | 判过是恶意/放行 | 同一句话配上新上下文，判据变了 |
| 工具输出：有没有泄露密钥 | 这段输出判过是干净/脏 | 输出格式改了，旧判据不再适用 |
| 磁盘哨兵：这个盘算不算真痛 | 痛到哪个程度、要不要叫人 | 阈值改了、盘换了 |
| 探针：这次算正常还是异常 | 上一次的结论和理由 | 探针版本升级 |
| 交易闸门：这个信号开不开 | 开/不开 + 凭什么 | 风控参数变了 |
| 报价/比价：这个价吃不吃 | 吃/不吃 + 基准 | 供应商回价、行情动了 |
| 定时任务：这轮做过没有 | 做过的结论 | 任务定义改了 |
| 告警抑制：这条是噪音还是真事 | 噪音/真事 | 同类告警的判据收紧 |

**一条硬提醒**：如果这件事**错了会亏钱/会伤人**，别指望账本替你把关——它只记住"上次判过什么"，
不负责"这次该不该"。"判不了"的时候它留悬位，那是给**你**回来看的，不是给你自动放行的。

## 0. 它跟 V1 的关系

| | V1 骨（`ganglion.py`，105 行，冻结） | V2 账（本文） |
|---|---|---|
| 干什么 | 一个 `content` 进来，两个值出去（判决 + 理由） | 把这每一次判决，留在账上 |
| 不干什么 | 不记事、不追变化、不管值多少 | 不判、不替代骨 |
| 改不改 | **一行不动** | 长在外面，另立变体 |

V1 的天花板很清楚：它记的是 `content → verdict` 的两个格子。
只要事态一变，它就把新的判决**覆盖**旧的——于是"它变过没有"这个问题，在 V1 里根本问不出来。

V2 的全部工作就是把那些被覆盖掉的东西接住。

## 1. 一节账长什么样

```
一节 = 一个点（链 A） + 三根轴（链 B） + 一个指纹
```

| 字段 | 是什么 | 谁写 | 什么时候写 |
|---|---|---|---|
| `verdict` | 判了什么：`1` / `0` / `None` | 骨 | 判决那一刻，一次 |
| `reason` | 凭什么 | 骨 | 同上 |
| `round` | 这是同一个问题的**第几回** | 账 | 每次新增，自增不停 |
| `value_score` | 这条账**值多少** | 事后回填 | 等它真被用上、真省了事，才给分 |
| `hits` / `last_hit` | 被翻过几次、最近一次什么时候 | 账 | 每次命中 |
| `ctx_fp` | 上次是在**什么情况下**问的 | 调用方 | 与判决同时 |

三条硬规矩：

1. **`round` 只增不改**。同一个问题的第 N 次判决是新的一节，不是覆盖第 N-1 节。
2. **`value_score` 初值必须是"未回填"，不能是 0**。0 分是"验过，不值"，未回填是"还没验"——这两件事合并，账本就学会撒谎了。
3. **`None` 不入账**。判不出来就说不知道、往上交，账上不留痕。V1 的这条铁律在 V2 里一步不让（理由见下节）。

## 2. 三个值：0 / 1 / 空

一个 `content` 进来，出去的是三个值当中的一个：`0`、`1`、空（`None`）。

这不是"三值逻辑"，也不是给答案多加了一个档位。**它是三个不同的动作。**

| 值 | 动作 | 我担什么 |
|---|---|---|
| `1` | 判是。证据够了，我认这个结论 | 放行错了，是我的错 |
| `0` | 判否。证据够了，我认这个结论 | 拦错了，是我的错 |
| 空（`None`） | **不判**。把这次观测退回去，交给上层 | 我说了算不了，责任转出去了 |

### 空不是"中间值"，空是"拒绝塌缩"

`0` 和 `1` 是同一件事的两半：**都塌缩了**。
空是没有塌缩。所以空不能排在 0 和 1 中间当一档——它根本不在那条轴上。

正确的排法是两条轴：

```
轴一：判了没有？   没判（空）────────── 判了
轴二：判成什么？                   0 ────────── 1
```

轴二只在"轴一 = 判了"的那半边才存在。把三条挤进一条数轴，是绝大多数"三态系统"出错的地方：它们把空当成 0.5，于是空迟早会被当成一颗软一点的 0 用掉。

### 空必须无损

账本存的是"这一次观测的结果"。空表示**这次观测没做成**，那就什么都没发生——账上的叠加态原封不动退回去。

所以空既不能落账，也不能改账：

- **落账就成了伪造历史**。账上出现"某次判了空"，后来读账的人会以为那次判过。历史里没有这一笔，才是真的。
- **改账就成了污染**。没判出来的那一次不许碰 `round`、不许碰 `value_score`——那些轴记的是"判过的事"的经历。

V1 里这一条是 `return None`，一笔不写。V2 一步不让：空只进一个计数器（丢了多少次），不占一格。

### 悬着的位置：空不占格，但「还在走」要留痕

空不落账，说的是**判决栏**不留痕。

但"这次还在走"本身得有个位置。不然"还在走"和"从没发生"在账上长得一模一样——那是另一种撒谎。

那个位置记三样：

| 记什么 | 是什么 |
|---|---|
| **差什么**（缺料 / 缺硬证据 / 配不上） | 方向：这根轴往哪儿长 |
| **走到第几圈** | 位置：它是这条账的第几次尝试 |
| **试过几次** | 进度：还在长，还是一直没动静 |

判决栏永远空着，**绝不填 0**。三个数加起来，就是"那根轴还没停"的证据。

塌缩的那一刻，悬位收掉、落一节账。**悬位不是账，是账之前的那个过程。**

再往下一层：**判 1 的那一刻，0 就已经钉在账上了**——它不是另一次判决，是同一件事的另一面。
所以空的意思不是"缺了半个答案"，是**这一对还没结成**。没结成的东西不能刻碑。

顺带一个分别：配不上（有旧节、情形变了）在悬位里是 `needs_recompute` —— 它不该往上交，它该去重算。这是三种质地里唯一一种"不是判不了"的空。

### 空有三种质地，混了就出事

| 质地 | 长什么样 | 该怎么办 |
|---|---|---|
| **无料之空** | 缺字段、缺上下文，根本不够判 | 补料。这不是判据的问题 |
| **无据之空** | 料齐了，判据不够硬，不敢下 | 升档，或交人 |
| **无配之空** | 旧账明明在，就是配不上这次的上下文 | **这不是空，这是"该重算"的信号** |

第三种最容易出事。它长得跟空一模一样（都返回 `None`），语义却相反：前两种是"我判不了"，第三种是"我该去判"。

把第三种当第一种用，结果就是系统永远在往上交——看着谨慎，实际是账被用坏了，重算的活一次也没人去做。

**判据要能分清这三样。** 分不清，就先别开账。

### 0 和 1 不对称，所以理由不是调试信息

`0` 是拦，`1` 是放。拦错伤体验，放错伤安全——两边一样重，但错法不一样。

只有 0/1 没有 `reason`，等于半个判决：说不清"凭什么"的账，事后既不能复核，也不能追责，更不能拿去调判据。
所以 `reason` 不是日志，是**这一节账的另一半**。

### 翻转不是判错

同一句话，第 3 圈 `0`、第 4 圈 `1`。

以前这被当成"系统不稳"、"数据脏"。有了圈号才看得清：**那是两次情形不一样，不是一次判错。**

三个值给的是"此刻是什么"，圈号给的是"它变过没有"。少了任何一个，另一头都会被误读。

## 3. 双螺旋：一条离散，一条连续

```
链 A ── 点 ──●────●────●────●──   离散：判了什么，可重放，可逐条核
链 B ── 线 ───────────────────   连续：值多少 / 谁翻过 / 第几回，一直在动
```

- **链 A 是离散的**：每次塌缩留下一个 0 / 1，判完就定死，可以重放。
- **链 B 是连续的**：三根轴永远不停在某个点上。今天的价值明天会变，使用是一闪而过的事件，圈号只往上走。

**这两条链都不是"结果"，是同一件事的两个面。** 只记 A，你得到一本能回放但不能更新的死账；只记 B，你得到一堆动来动去但说不出"当时判了什么"的流水。

### 翻转只存在于圈号里

```
第 N 圈   1
第 N+1 圈 0     ← 这里发生了一次翻转
```

没有 `round`，你只能看见"现在是 0"，永远看不见"它曾经是 1"。

**一个只记当下状态的系统，和一个能说出"它什么时候变的、变成什么、为什么变"的系统，是两种东西。**

## 4. 六个取用面，一个地址

同一节账，可以被六种方式取用——不需要六份存储，也不需要接口层：

| 取用面 | 问的问题 |
|---|---|
| ① 值 | 这条账值多少？ |
| ② 判决 | 当时判的是什么？ |
| ③ 缓存 | 有人翻过它吗？ |
| ④ 节 | 这是第几回？ |
| ⑤ 时刻 | 什么时候判的、什么时候被翻的？ |
| ⑥ 可借 | 上次的情况跟这次一样吗？**一样才准抄** |

**互用靠地址统一，不靠接口对齐。** 六个面共用同一个 key，所以任何一个面取到的都是同一条地址上的东西。
**但"同一条地址"不等于"同一节"**：一条地址可以判过很多圈，各面默认取最新一圈。要把六个面钉在同一节上，用 `six_port(key, ctx_fp, rnd=3)` 指定圈号；不指定时锚最新一圈。

这条的代价也很实在：**key 一旦撞格，六个面会一起压成一格。** 所以 key 的构造不是实现细节，是账本的命门——调用方传全文摘要，不要传截断前缀。

### 六面是网，不是清单

这六个不是六条并列的读法，是一张交叉网：**任意两面交叉，才定位得了一节账。**

| 交叉 | 问出什么 |
|---|---|
| 判决 × 节 | 第 1 圈就是 1，可能只是碰巧；第 5 圈还是 1，才叫稳 |
| 缓存 × 时刻 | 被翻过 3 次，都是三天前——该重判了 |
| 可借 × 判决 | 上次那个 1，是什么情形下判的？情形不合，不许抄 |

单看任何一个面都会失真：只看见"现在是 0"，看不见它曾经是 1；只看见"判过 1"，看不见那是在什么情形下判的。

所以有一条硬约束：**接口可以加，面永远是六个。**

新加的方法（销悬位、追加写、压实），不许变成第七、第八个门——它只能是"时刻 × 节"上多记一笔，或者"节 × 缓存"上多走一步。数是六，网才收得紧；一旦真的长出第七个面，六个面的交叉关系全部重算——那是换一本账，不是加一个方法。

## 4.5 Z 轴：五件

时间这一维，落成五件。前四件管"它怎么走"，第五件管"它怎么死"。

| 件 | 一句话 | 没有它会怎样 |
|---|---|---|
| **每节自带钟** `record(ttl=)` | 窗写在每一节上，不是整本账共用一个 | 拿肠子的节奏管神经元：该忘的不忘，该记的记不住 |
| **收口期限** `decide_by` | 到点必须收；收不了就留痕"到点无据" | 悬位挂一辈子，看上去永远"正在查" |
| **太新不借** `min_age` | 刚判完就问一遍的，不许借 | 同一瞬间的抖动被当成结论 |
| **回溯** `revisit` | 拿今天的判据重演旧圈，旧节一个字不许改 | 只看得见"情况变了"，看不见"判据变了" |
| **遗忘** `prune` / `sweep_ttl` | 平淡节褪成梗概（判决、圈号留住）；过窗的节先归档再立墓碑 | 账只会长不会死，最后烂成一团 |

一条总则：**谁的钟谁上发条。**

`ttl` 记在节上而不是账上，是因为同一本账里可以同时住着两分钟一圈的器官和一年一圈的保险。给一个统一默认值，等于拿肠子的节奏管神经元——该记住的忘了，该忘的记一辈子。这也是"一个默认值都不给"最硬的一条理由：**默认值一给，时间本身就没了。**

关于第五件（三档遗忘，2026-11-04 定案：记忆是渐暗的，不是灯开关）：**鲜活（全记）**是被翻过的、在翻转序列上的、revisit 过的、打过分的以及最后几圈；**梗概（大概记一点）**是判过、没人翻过、也没参与翻转的平淡节——`prune()` 把它们褪成梗概，判决和圈号留住，情形指纹、借账细节褪掉；**忘（墓碑）**只有按钟那把刀 `sweep_ttl()` 能动，而且**先归档后动刀**（不给归档位置就不动刀——打印一句返回 0，留不下底就不写；这把刀**绝不抛**，调用方夹在 append 和 save 中间那条老承诺不破）。两把刀都**不整条抽走——原地占位，圈号一个字不许乱**。遗忘本身也必须在账上看得见，否则就是偷偷改账。

## 5. 三条纪律

### ① 有人会翻，才配记

账本被养爆，几乎从来不是"记得不够好"，而是**记了大量永远不会被回头看的节**。

记之前问一句：**这一节，将来的谁会来翻它？** 答不出来就不记。
免费的判据、走一遍就丢的过程节点、没人会验的中间状态——统统不配占一格。

### ② 配得上，才叫可借

`key` 命中 ≠ 可以抄。
**（旧判决 × 这次的上下文指纹）对得上**，才叫可借。

指纹太粗（比如只用一个会话 ID），会把"不同时刻的同一句话"当成同一节，直接抄——抄得多，错得也多。
指纹太细（细到每次都不同），等于没有指纹，一次也借不上。

**指纹必须刚好卡在"一个判决能成立"的那个尺度上。** 这个尺度没有通用答案，得自己量。

### ③ 抄了，就得有保鲜期

这条是前两条的补丁，也是最容易被忽略的一条。

**抄 = 宣布"这次什么都没发生"。**
可是账本存在的意义，恰恰是记录"发生过的变化"。

所以：抄可以，但抄来的判决必须带一个窗。窗内可以借，**过窗必须重算**。
涉及价格的窗短，涉及偏好的窗长——但**没有窗的借，是对账本的背叛**。

## 6. 它接得上什么、接不上什么

**横轴是全的，纵轴不全。** 这句话是这套东西最准确的自我说明。

- **横轴（业务）**：全。
  它不认业务，只认"这件事能不能被判成一个值"。报价、合规、消息过滤、搜索剪枝、动态规划——对它都是同一件事。

- **纵轴（难度）**：不全。
  它接得住"可枚举、可分解"的活；接不住需要**跨分支共享剪枝**的活（那类剪枝是约束，塞不进"一个内容进"的签名）；更接不住输出本身就是证明的活。

主动交边界，是因为**一个不肯说自己接不住什么的东西，没人敢用它接重活**。

**「没做」和「空格」是两回事，别混着读。** 实现层欠下的（没做的功能、只当默认留着的口径）逐条写在 README 的 [Known gaps 表](../README.md)，每行第三列写死「钉在哪 / 为什么留着 / 什么条件下关」——round 51 清过一遍尾，round 52 又关掉两行（时间线 `recent(n)` 的三件口径定死、压实底 `keep=` 保留最近 N 份带三件套），能关的（补测试）都关了，关不了的给了条件，不含糊行。表二那六个空**永远关不掉**：那是使用者的空格，我们给带说明的默认值（如 `decay()` 默认一周半衰）也不等于替你填 —— 默认值要带三件套（默认 + 说明 + 可调），关的条件是使用者给出他自己的口径。

## 7. 怎么自己验（方法，不是结论）

在一份**你自己的真实流水**上，跑四个对照：

| 实验 | 你要回答的问题 |
|---|---|
| **A. 全记 vs 全借** | 账本从多厚变到多薄？你少算了多少？ |
| **B. 借了之后，账还能看见变化吗** | 同一批流水，全记时认出几次变化？借了之后认出几次？ |
| **C. 粗指纹 vs 细指纹** | 借到几次？其中几次跟实际结果不一致？ |
| **D. 六面是否真的通** | `six_port(key, ctx_fp, rnd=)` 六个面是不是同一个圈号？分头取 `by_value` / `by_verdict` 时，各面取的是不是同一圈？ |

实验 B 最容易被跳过，也最值钱。**如果你只做一个实验，做 B。**
它会把"复用"和"记账"这两件事的矛盾，直接摊在你面前。

**判断标准不用我们给**：只要 B 的答数明显小于 A 的答数，你就已经摸到这本账的核心了。

## 9. 与相关工作的差别（一句话版）

- **缓存**问「省了多少」，用命中率和淘汰策略量它。
- **审计日志**问「谁改了什么」，用不可抵赖量它。
- **账本**问「这一节凭什么成立」，用值、用、圈三根轴量它。

Ganglion 的骨是缓存的外形，V2 的账是账本的芯。**两边的人都只做了一半，中间那条缝一直空着。**

## 10. 定型：什么不许动，什么必须你自己填

这套东西要通用，就得有一半是死的、一半是空的。

**死的那半是尺子，空的那半是你的账。**
尺子也留给别人改，他就抄不准；别人的账也替我们定死，他就是在用我们的业务。

### 表一 · 不许动（动了就不是账本，是别的东西）

| 不变量 | 为什么不能动 |
|---|---|
| **签名**：一个 `content` 进，`0` / `1` / 空 出 | 这是尺子的刻度。改签名 = 换一把尺，别叫它同一个名字 |
| **空不入账** | 记了空就是伪造历史。这条一破，账上所有"没发生"都不可信 |
| **`round` 只增不改** | 覆盖一次，就永久丢失一次翻转的证据 |
| **`value_score` 未回填 ≠ 0** | 合并这两个值，账本就开始撒谎 |
| **配不上不许借** | key 命中只证明"问过同一件事"，不证明"情形一样" |
| **抄了必留痕**（抄了哪一节、抄的时候核没核） | 不留痕的借，事后对不上账，也没法追责 |
| **0 与 1 互为对面**：判 1 就是判了"不是 0"，对面与判决同一刻成立 | 这不是约定，是结构。
谁想改"什么算翻转"，等于想把互补项改成不是互补项 |
| **翻转不归使用者定义**：同址相邻两圈判决不同 = 对面显形一次 | 翻面是 0/1 互补关系在时间上的投影，不是业务参数。一让它可定义，"变了"就会被人当"数据脏"洗掉 |

### 表二 · 必须你自己填（我们一个默认值都不给）

| 你必须回答的问题 | 为什么只能你来答 |
|---|---|
| 你的**重算成本**是多少秒？ | 你的判据多贵只有你知道。这个数决定"什么值得落盘" |
| 你的**保鲜期**多长？按什么分档？ | 价格按天、偏好按半年。给一个统一值，等于替你的业务判错 |
| 你的**指纹**多粗？ | 粗到会话、细到轮次，还是更细。只有你知道"什么算同一个情形" |
| 你的**`value_score`** 怎么打分？ | "真拦下一台车"算几分，是你店里的规矩，不是我们的 |
| 判不了的时候**交给谁**？ | 空必须有出口。没有出口的空，等于静默失败 |
| 哪些过程**不记**？ | 你的负载里哪些节点永远没人翻，你比我们清楚。答案交给 `Ledger(admit=...)`：期望收益 = 重放概率 × 重算成本 − 写入成本，≤ 0 就在记账口源头拦下（不进链、不写流水）。不传 `admit` = 全记 |

**六个空，必须填。**
填不满就先别开账——不是不能跑，是跑出来的东西没有一处是你自己的判断。

### 表三 · 已知的错法（反例，都是踩出来的）

| 错法 | 会发生什么 |
|---|---|
| **把命中率当指标** | 对账本来说，命中率高是**坏消息**：说明你抄太多、眼睛闭上了。缓存该追的东西，账本该警惕 |
| **借一节 = 省一次算力** | 借一节同时**宣布"这次什么都没发生"**。而翻转只存在于被借掉的那一节里。省得越多，看见的变化越少——方向是确定的，比率你自己量 |
| **拿会话 ID 当指纹** | 同一个会话里换了好几个情形，全被当成同一节抄掉——"配得上"变成"碰上了" |
| **截断前缀当 key** | 长前缀的模板题会把几十个不同问题压成一个地址，六个面一起串味 |
| **把翻转当业务定义去商量** | "我们这儿不算翻转"——那你就是不想让对面显形。0 和 1 是同一件事的两个面，这一条没有商量的余地 |
| **判不了就硬判成 0** | 把"不知道"降级成"没问题"。这是最贵的一种省事 |
| **把"配不上"当"不知道"** | 系统永远在往上交，看着谨慎，实际重算一次也没发生 |
| **只记走路的节点** | 树搜索那种每个节点都单独记一遍的账，是纯负债，哪怕它每一条都对 |
| **账本只存在内存里** | 进程一停，账归零。跑起来像成功了，重启一次全忘 |
| **没窗的借** | 借来的判决永远不会过期，于是系统永远活在上一个情形里 |

### 一句话

**定型定的是「你必须回答哪些问题」，不是「你必须这样回答」。**

定完之后，别人拿它测自己的数，结论可能跟我们完全相反——那才叫通用。
要是测出来都跟我们一样，说明我们只是把自己的业务塞给了他。

## 11. 落盘与并发：谁是正本

一条规矩，四句话：

1. **流水是正本，快照是压实产物。** 只追加的文件不会互相吃；重写整本会的。
2. **`save()` 不吃账。** 它写快照前先把流水里别人刚写的行吸收进来，原子替换（`.tmp` → `rename`），**不清流水**。清流水会吃掉别的进程正在追加的那一行——我们实测过，丢得悄无声息。
3. **`compact()` 才清，而且不是清，是拷底 + 截空。** 先拷一份 `<流水>.<纳秒>.<pid>.compact` 底，再把正本截空 —— 文件自始至终是同一个（inode 不变，写者手里的句柄不会变成「往旧代写」的坑）；底默认**保留最近 10 份**（`compact(..., keep=N)` 可调，`keep=None` 一份都不删；删之前两道闸：只删我们起的名、只删已经全部进快照的底 —— 删得掉才删，round 52）。压实要在没人写的时候做：多写者同时写的时候压，等于在别人写字时把纸抽走。
4. **重演必须幂等。** 同一节既在快照又在流水里，认它一次。快照里记着"流水读到哪个字节了"，读的时候接着读，不从头再来。
   判"是不是同一节"要**比内容**，不能只比时间和判决——2026-10-31 那版只比 `(ts, verdict)`，两个方向都错：同一毫秒判的两圈被当成一节吃掉，同圈不同内容又会记成 `[1,2,3,2]`，`flips()` 当场报出不存在的翻面。
5. **借这一下也要进流水。** 只在内存里 `hits += 1` 是读-改-写：两个进程同时借，后写的盖掉先写的。而 `prune()` 恰恰靠 `hits>0` 判断"别忘这节"——盖掉之后就是**借得越多、忘得越快**，方向和整本账的主张正好相反。
6. **借票也必须落盘。** `probe()` 的 `journal` 是必填的：给路径就把这一借落成一行，多进程谁也不盖谁；真不要落票就明写 `journal=False`（只许单进程，而且 `prune()` 会因此借得越多忘得越快）。不传就报错 —— 默认"不落账"，等于替每个用它的人挑好了那个坑。同理 `LedgerGanglion(L, journal=...)` 不给就构造不出来：骨和账焊在一起，就意味着它一定会借。
7. **收口也要落账。** `resolve()` 的 `journal` 同样必填。时间逼的收口（`forced=True`）尤其要留痕：不留，进程一崩，这笔怎么没的就没人知道了。收口那一行带 `forced` 和 `by`（谁收的）。
8. **压实要拿锁，第二个让路，而且让路要说清楚。** 三个返回值分得清：`<备份路径>` 压成了 / `None` 本来没流水 / `False` 有人在压、这次让路；`stat["compacted"]` 与 `stat["compact_skipped"]` 分别计数（cron 跑一夜，看得出压过几次、让过几次）。烂锁要判**人还在不在**，不只判老不老：锁里记 pid，主人还活着就不许抢，压实过程每 15 秒续一次 mtime —— 否则一本账真压过 5 分钟，互斥会随账本长大自己失效。
9. **压实前按磁盘对齐，但对齐是合并、不是覆盖。** 手上那份可能比磁盘旧（别人刚压过）；可反过来，手上也可能有磁盘上还没有的（自己 `record()` 了还没 `save()`）。只按磁盘覆盖 = 把调用方还没落盘的账当脏数据扔了，丢的还是静默的。所以对齐走 `_merge_from`：同圈同内容不重记，别人的悬位也收下，圈号撞了只给**新并进来的**那一节顺延到队尾，盘上已有的号一个字不动（历史不许改），顺延后按圈号重排链，保证"链里第 i 节 = 第 i 圈"。`save()` 同理：读进来之后硬盘变了，先合并再写（否则就是教科书式的丢更新）。
10. **Windows 上"正在换页"不是坏本。** 别人拿着快照或流水时，`os.replace` 会 `WinError 5/32`、`open` 会 `PermissionError`。`save()` / `load()` / `compact()` 都重试约 2 秒；等不到就让它报错 —— 宁可吵，不许装作存上了。
11. **拷底截空的窗口要补。** 吸收读到 EOF 之后、拷底截空之前，任何一次追加都会落进正要被拷走的那份。压实之后要从**那份底**里**接着上次消费的位置再读一遍**（正本已经截空，窗口里的行只在底里）；读的一方也要扫一眼没登记过的 `.compact` 备份（压到一半崩了，行还在里面）。宁可慢一点，不许少一行。

为什么值得写进纪律：**丢账不报错**。程序照样跑，账上少一节，你在半年后对账时才会发现——那时候你已经拿它当过证据了。

## 12. 署名：谁写的

一节账，除了判了什么、凭什么，还要记**谁说的**。

```python
from ledger import Ledger, addr

k, ctx_fp = addr("这轮探针通不通"), "fp|probe"
L = Ledger(writer="disk-sentinel", ttl=3600)   # 这本账谁的，声明一次
L.record(k, 1, "没卡", ctx_fp)                 # 每节自动带上署名
L.record(k, 0, "替你记的", ctx_fp, writer="helper")   # 代写可覆盖
print({w: [(n["verdict"], n["reason"]) for n in ns]
       for w, ns in L.by_writer().items()})    # → {'disk-sentinel': [(1, '没卡')], 'helper': [(0, '替你记的')]}
```

三条：

1. **没有默认值。** 不明说 `writer`、也不每节传，`record()` 直接抛 `ValueError`。不要给它编一个 `"unknown"` —— 编一个默认署名，等于给整本账发了一张万能免责条。
2. **悬位也要署名。** "还在走"同样是一句话，也有说这句话的人。
3. **落盘保留。** 快照记账本归属，每节记署名；重演时不换成读的人的名字（读的人不是写的人）。

为什么值一格：账本最值钱的一句是**"你说的我查得到"**。没有署名，查到的只是"有人说过"。

署名存了就得有读法：`by_writer()` 按写者分组。否则想读只能伸手进 `nodes[key][i]["writer"]` —— 那是私货。加读取接口不算加面。

## 12.5 地址是公开的

`addr(text)` 是模块级函数，和内部算键**同址**：你必须能用它提前算出"这条账会在哪个地址"。

**两条得先说清**（不然会误用）：①先剥标点空白，`你好，世界` 与 `你好世界` 同址；②**只取前 64 个字符**，64 字之后改什么都同址。要拿它当"这是不是同一件事"的凭据，判别词请写进前 64 字。

以前它只在内部（`_make_key`），例子也照着私货写——外人进来第一件事就是把手伸进你的私有函数。**一个要用却不敢公开的函数，等于没给你。**

## 13. 上手速查

第一次接入从这里开始。**只读这一节也该接得进去**——面叫什么、入口在哪、给回来的是什么。

### 13.1 账的地址是内容，不是业务实体

`addr(text)` 是对正文取摘要。所以“一个任务一条账”是错的：同一句日志来两次是同一个地址，不同任务说了同一句话也是同一个地址。想按任务查，就把任务名拼进正文再 `addr(整句)`。

### 13.2 六个面 ↔ 方法名

| 面 | 取法 |
|---|---|
| ① 值 | `by_value(key)` |
| ② 判决 | `by_verdict(key)` |
| ③ 缓存命中 | `by_cache(key)` |
| ④ 圈 | `by_round(key)` 返**整串**圈号；`six_port()` 的 ④ 返**这一节**的圈号 —— 同名不同义，别混用 |
| ⑤ 时刻 | `by_time(key)` |
| ⑥ 可借配对 | `by_pair(key, ctx_fp)` —— 这一面要指纹，别的五面不要。**注意两个入口的宽严不同**：`by_pair` 在两边都没给指纹时算配上（同一个默认组，否则空指纹永远借不到）；`six_port` 的 ⑥ 要求两边都非空才 True |

懒得一个个取：`six_port(key, ctx_fp="", rnd=None)` 一次给 `[六面字典, 几面有数据]`；`rnd` 不给就锚最新一圈，六个面保证出自**同一节**。（“接口可以加，面永远是六个”—— 加方法不加面。）

**时间线是另一件事（不是第七个面）**：`recent(n)` 跨地址取**最近 N 节**，只读、不改链、不动统计、不落账。三件口径 round 52 定死：① 查什么 = 所有地址上的每一节（节点自带 `key`）；② 按什么排 = 节自带的钟 `ts` 降序（跨地址没有共同链序），同 `ts` 按圈号降序、再按地址升序；③ 边界给谁 = 墓碑不算、褪色节算，n 从最新往回数、不够就全给、`n <= 0` 给 `[]`、没有钟的节跳过。单地址的时间序照旧 `by_time(key)`。

### 13.3 五个入口在哪儿

| 你要的 | 在哪儿 |
|---|---|
| 太新不借 `min_age` | `probe(key, ctx_fp, checked, min_age=...)` |
| 收口期限 `decide_by` | `open_pending(..., decide_by=ts)` → `due()` |
| 落账 `journal`（必填） | `probe(..., journal=)` / `resolve(..., journal=)` / `LedgerGanglion(L, journal=)` |
| 落信号 / 落两笔 `journal`（必填） | `signals(..., journal=)` / `expect(..., journal=)` / `actual(..., journal=)` —— 同一条规矩：给路径就落，给 `False` 明说不落（单进程），不给就报错 |
| 悬位也要落盘 | `append(流水路径, key, verdict=None, ...)` |
| 指纹 | `make_ctx_fp(任务, 判据版本, 机器)` —— 模块级，公开 |

`Ledger(...)` 构造器只认 `writer / ttl / deliver / now`。`min_age`、`decide_by` 不是构造参数（别在这里试，会 `TypeError`）。

**几个返回值和三种「读法」（都是错了不吭声的那种）**：

| 调用 | 给回来的是 | 别写成 |
|---|---|---|
| `probe(key, fp, ...)` | **整节 dict**（`verdict` / `reason` / `round` / `hits` / `ttl` …），不是判决值 | `v = probe(...)` 然后把 `v` 当 1/0 用 |
| `by_pending(key)` | **单个 `Pending` 或 `None`**，不是列表 | `if L.by_pending(k):` —— `bool(Pending)` 恒假，这个 `if` 永远进不去 |
| `Ledger.load(path, ...)` | **类方法**，返回一本新账 | `L2.load(p)` 再指望 `L2` 有数据 |
| `Ledger.load(不存在的路径)` | **报 `FileNotFoundError`** | 以为拿到一本空的 —— 那说明路径打错了 |

读一本还没写过的账，第一次请显式 `Ledger.load(p, empty_ok=True)`：让"读不到"和"空"长得不一样。

### 13.4 `check()` 判不出时给的不是 `None`

`LedgerGanglion.check()` 的悬位分支返回 `Pending` 对象（`bool(Pending) is False`），不是 `None`。写 `if v:` 会把悬位当成“没有判决”或“有判决”，两种都错。一律：

```text
v is 1        # 是
v is 0        # 否
其余          # 悬位：问 Pending 自己的字段（why / need / tries / round / decide_by / first_ts / last_ts），或 by_pending(key)
```

`Pending` **没有** `.pending` 这个属性，`by_pending()` 也要带 key（`by_pending(addr(正文))`），而且给回来的是**单个 `Pending`**（`None` 表示这一句没有悬位）—— 不是列表，`if L.by_pending(k):` 永远为假，请写 `is not None`。

### 13.5 `flips()` 的 kind 只有两种

- `"情况变了"` —— 世界动了（新一圈，不是判错）
- `"判据变了"` —— 我们动了（`revisit` 造出来的）

分不清“我改了判据”和“事情变了”时，看这一栏。

### 13.6 `append()` 的参数顺序（错位现在会报错）

`append(path, key, verdict, reason, ctx_fp, ...)`：**第一个是流水路径**（必须以 `.jsonl` 结尾），第二个才是地址。

少写一位路径会把地址当文件名，写出一条 `key=null` 的假账，**而且不报错**。现在四种错位（地址当路径 / key 空 / key 不是字符串 / 判决传成 "对"）当场 `ValueError`，体检「记错位置的账当场报错」钉住。
记账口 `record()` 守**同一把尺**（体检「记账口也守一把尺」）：判决只认整数 `1` / `0`，`'对'`、`2`、`1.0`、`True` 一律拒；判不了就走悬位。同一道口子上还有第二道闸 —— 体检「该不该记在源头拦」：判据说不值得记的，`record()` 返回 `None`，不进链、不写流水；收口、订正、重演不过闸。曾收过的 `-1` 没有任何语义、配对面会崩，已从白名单删掉。

### 13.6½ 流水换代：偏移只对那一代有效

流水被压实改名之后，新建的那个 `.jsonl` 是**另一代**文件。上一代记下的“读到第 8000 字节”对新文件没有意义 ——
新文件只有 300 字节时，`size < start` 会被误当成“已经读完了”，中间那段就静默跳过。

现在的规矩：**读到位置比文件还大 = 换了一代 → 从 0 重读**。同理，已登记的压实备份也记着自己被消费到第几字节
（快照里的 `sealed`），备份后来又被别人（拿着改名前的旧句柄）写长了，就只补读那截尾巴。

这两条只有在**慢文件系统**（网络盘、共享盘、虚拟机里的挂载盘）上才会露头：本地盘上百次都好好的，
到了那儿偶尔丢一节。慢文件系统不制造 bug，它只负责不放过。

### 13.6¾ audit()：未重演 / 断链 / 坏行，三笔分开报

`audit(path, journal=)` 只读不改，返回全整数读数：`journal_bytes`（正本现长）、
`consumed_bytes`（吃到哪）、`unabsorbed_bytes`（写了没重演的尾巴）、`backup_bytes`
（已消费的压实留底）、`rows_on_chain`、`bad_lines`、`aligned`。判读顺序：先看
`unabsorbed_bytes`——不为零只是**还没人重演**；带 `journal=` 重演后仍不齐才是真缺口；
`bad_lines` 独立成轴（§13.8 那条"会被跳过"的老账从这里看）。来源：2026-11-17 外部
issue「borrow 后流水 +1 行、链 0 行、verify 红」——账没丢（重演后 hits/borrows 都在），
红的是拿快照对流水的读法。钉住：`tests/test_audit.py` 5 条。

### 13.7 V1 的一条老实话

`ganglion.py`（V1，105 行，冻结）在 `processor` 返回 `None` 时，会把 `(None, reason)` 记进 mem，并在 TTL 内**遮蔽**同一句的后续判决 —— 换个判据也判不动。

这不是文档没写清，是 V1 的行为：它记的是“这次判过了”。要“空不落账”，用 V2（`record(None)` 直接抛错）。V1 我们一行不动（表一）。

### 13.8 出站口与结算（第一刀，2026-11-06）

**一、出站口：被问才答之外的第三种开口 —— 账内状态自己叫醒。**

| 圈况 | 素名 | 什么时候响 |
|---|---|---|
| 翻了 | `flip` | 相邻两圈判决不同（`flips()` 现成） |
| 卡了 | `stuck` | 转满 `threshold` 圈（默认 3）仍无进展：悬位没塌缩 / 判决不更新（两档） |
| 通了 | `converged` | 这一节在窗内**且确实被翻过**：答案问就有 |

- `L.stuck(key=None, *, threshold=3, now=None)` → 事件清单，每条带 `kind` 与 `idle` —— **这条地址卡了多久没动**（秒）。判据只数圈、不看墙钟（快的线快转、慢的线慢转，3 圈对谁都公平）。两档：
  - `kind=悬位没塌缩`（第一档）：悬着的位置被问满 `threshold` 圈还没塌缩。「动」只有两种：落下新的一节、悬位塌缩，**再问一次不算动**（`tries+1` 不重置 `idle`，那是原地转圈）。
  - `kind=判决不更新`（第二档）：链上落满 `threshold` 圈真实判决、**判决从头到尾一个样** —— 圈转满了，判决栏一个字没动过。翻过面的不算（更新过就是有过进展）、墓碑不占圈、第一档报过的地址不重报；`idle` 从第一圈起算（判决从那一刻起没更新过几秒）。没钟的链报不了就不报。
- `L.signals(*, journal, key=None, threshold=3, now=None, kinds=("flip","stuck","converged"))` → 三型同框，`journal` **必填**（同 `probe` / `resolve`）：给路径就每条信号落一行 `{"t":"signal", …}`，给 `False` 只查不落（单进程），不给就报错。
- 信号是**日志，不是账**：不进链、不改判决、不塌悬位；换个人重演回来只在 `stat["signals"]` 数得出响过几回。
- 只报事实，**不替你算叫不叫醒**：值不值得开口（期望收益 = P(有价值) × 收益 − 叫醒成本）是外面那道闸的事。
- **边界（写死，别把信号直接接成调用）** —— 谁管什么，一张表说完：

  | 谁 | 管什么 | 不管什么 |
  |---|---|---|
  | `L.signals()` / `L.stuck()` | 什么时候**可能**值得开口（翻了 / 卡了 / 通了，事实） | 不算划不划算，不给动作 |
  | `admission` 期望收益闸 | 这一**笔记不记**（接在 `Ledger(admit=)` 上） | 不读信号、不知道响过没 |
  | 「叫不叫醒」 | 调用方拿信号**现算**的第三处，同一把尺 | 账本不替你算，也不提供叫醒动作 |

  - 同一把尺：**期望收益 = 重放概率 × 重算成本 − 写入/叫醒成本，`≤ 0` 不记不叫**（当没响过）。
    信号侧把「重放概率」读成「这条之后真会有人来问的概率」，「写入成本」读成「叫醒成本」，式子一个字不改。
  - 四条禁令：① 信号不进链、不改判决、不塌悬位 —— 拿到信号不许直接 `record()` 当结论；② 事件字段里没有 `action` / `gain`，**读不出「该叫了」**，别去事件里找批准；③ 叫醒必须过期望收益，`≤ 0` 当没响过，`converged` 也一样（「问就有」≠「值得问」）；④ 两条链互不 import（双螺旋）—— `admission` 不读信号、`signals` 不读判据，谁写错另一侧不跟着错。
  - 钉住它：体检「信号不越权」（45 项之一）。

**二、结算：两行结构，预计一笔、实际一笔。**

- `L.expect(key, 数字, *, journal, writer=None)` — 判决那一刻的「我预计 …」，`ts` 是当下（预约不算未来）。**不许事后回头改**：拿结果粉饰当初的判断，校准就白做了。
- `L.actual(key, 数字, *, journal, writer=None)` — 事后由现实回填的「实际 …」，`ts` 是后来。什么算「实际」（取行为还是取嘴说）由使用者定，本件只给格式。
- `L.gap(key=None)` — 差值 = 预计 − 实际，回流成校准度的原料。**缺一边如实报 `None`：缺笔不是 0 分** —— 还没结算 ≠ 正好猜中。
- 差值折成 `value_score` 的口径在**可选工具层** `tools/gap_value.py`（三件套铁律：空格、默认值、说明缺一不可）：`score = scale / (scale + |gap|)` —— 正好猜中 1.0、差满 `scale`（默认 1.0）腰斩、方向不偏不倚、永不等于 0（「不准」≠「验过不值」），缺笔原样传 `None`。**不硬绑主链**：工具不 import 账本、不回填；回不回填、回填哪一圈（`backfill_value`）、权重怎么改仍是使用者的空格。
- **多笔按 `ctx_fp` 合成一个数**（round 48 示例）：`aggregate(buckets)` 照条件概率表两步走 —— 情形内 `score|fp = mean(score(gap))`（**先折后平均**：高估 `+1` 与低估 `−1` 不许在差值层互相抵消成假的满分），情形间 `value = Σ P(fp) × (score|fp)`，`P(fp)` = 该情形有效笔数 / 总有效笔数。`None` 不投票（缺笔不进笔数），某情形全缺整个让位；一笔有效数据都没有 → `None`。中间那张条件表用 `by_context(buckets)` 看。输入两种形状都收：`{fp: [笔, …]}` 与 `[(fp, gap[, age]), …]`（笔可以是裸 gap，也可以是带时间的 `(gap, age)`）。
- **回填时机与时间衰减**（round 49 默认口径）：`decay(age, *, half_life=604800)` → `w = 0.5 ** (age / half_life)`（默认一周半衰；`age` 与 `half_life` 同单位，按圈数衰减就都传圈数）。**顺序不进聚合**（求和可交换，谁先谁后一个样），进聚合的是权重：情形内 `score|fp = Σ w·score / Σ w`、情形间 `P(fp) = Σ w(fp) / Σ w 总`；没给 `age` 的笔 `w = 1.0`（不编时间、不猜年龄，整条链退化成「笔数占比」= round 48 行为），给了 `age` 的缺笔照旧不投票。**三件套空格**：衰不衰、半衰期多长、按频次/重要性加权，都在调用方手里；回不回填、回填哪一圈仍不碰主链。**整条线的合体用例**（多笔回填 → 衰减加权 → 情形聚合，含落盘往返、顺序无关与缺笔护栏）在 `tests/test_decay_aggregate_line.py`。
- 两笔只收数字、地址要真、`journal` 必填、要落账必须署名 —— 和别的口子同一把尺。
- 流水是正本（`{"t":"expect"}` / `{"t":"actual"}` 每一笔都留着），快照也带最新一对（`sides`）；内存里同一地址只留最新的一对，合并时同一侧按 `ts` 比、后写的算数。

体检里四条钉着它：「出站口落账」「停滞第二档」「预计实际两行」「信号不越权」（`python conformance.py`，45 项）。
