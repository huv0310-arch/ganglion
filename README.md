## 这东西到底是个啥（一句人话）

**一个记仇的小本子。** 一件事你判过一次（该拦、该放、该等），它记下来；下次同一件事再来，它不重算，直接翻给你看。

- 它**不判断得对不对**，只负责"这题我判过了，答案是几，谁判的，什么时候判的，凭什么判的"。
- 判不了的时候它**不会瞎猜**，会留一张"悬着的票"（还缺什么料、什么时候必须要答复），等你回来收口。
- 账记在文件里，断电、重启、换进程都还在，而且是**只往后添加**——整理（压实）只搬位置、不删节。
  **一个诚实例外**：压实会把"这节被翻开过几次"并进那一条，之后换个人拿新指纹再来同样的读，这一次记不上——
  判定和圈号一个字不改，但"被借过"的流水会少一笔。要查"谁借过"，别在压实之后就断言没有。

一句话：**省下重复的那一遍，并且事后能回答"当时为什么这么判"。**

## 两件别人替不了的事

**一、它有三个值，不是一个缓存有没有命中：`1` / `0` / `正在`。**

普通缓存的键只有"有"和"没有"，于是"还没到时候"这种状态只能被硬拧成 0 或者 1——**那是撒谎**。
账本给"正在"一个正经位置（悬位），并且不只记一句"待定"，还记：**差什么料、第几圈、试过几次、什么时候必须给答复**。

- `1` = 成了
- `0` = 不行（注意：`0` 只配"快短路"，不配"永久否定"——同一个词换个上下文可能就该是 1）
- `None / 悬位` = **正在进行**，答案还在长，不是没有答案

**二、它记的不是"现在是什么"，是一条时间轴。**

同一个地址，第 1 圈判 `1`、第 2 圈判 `0`，**两节都留着**。没有轴的系统里，"现在是 0"会把"曾经是 1"直接擦掉——**被擦掉的那一节，才是真正值钱的那一节**。

所以它答得出普通缓存永远答不出的三句话：

| 问 | 答 |
|---|---|
| 它变过没有？ | 变过，第 2 圈翻的面，两节都在 |
| 为什么变？ | 分得清是**情况变了**（世界动了）还是**判据变了**（我们动了） |
| 当时凭什么这么判？ | 谁判的、用什么指纹、什么理由，都在那一节里 |

一句话：**缓存存"现在"，账本存"怎么走到现在"。** 全对的历史是最没用的历史——翻过面的那几节，才是这套东西的价钱。

**一句反直觉的，先说了免得误会**：**命中率高不是好消息。** 借一节旧账，等于宣布"这次什么都没发生"，
而"翻转"只存在于被借掉的那一节里。别拿命中率当仪表，看**借了之后被翻掉的比例**——账越省事，你越看不见变化。

想往下看它凭什么这么设计：[docs/SIX_MINDS.md](docs/SIX_MINDS.md)——当初六个想法（翻书 / π值记忆 /
叠加态 / 菱形 / 双螺旋 / 时间 Z 轴）各自落在哪一行代码、能用什么判据验它没跑偏。

## 适合装在哪些地方

凡是"**同一件事会被反复问、而且每次答案都该一样**"的地方，都该装一个：

| 场景 | 它替你记住什么 | 一句话 |
|---|---|---|
| **AI 前门** | 这句话/这个链接/这份附件，判过是恶意还是放行 | 同一条垃圾话刷十遍，只判第一遍 |
| **工具输出** | 这段输出里有没有密钥、有没有越权内容 | 判过的不再逐字扫 |
| **磁盘/资源哨兵** | 这个盘这次算不算"真的痛"、要不要叫醒人 | 报警不重复，避免同一个盘每小时喊一次 |
| **探针/健康检查** | 这个探针现在算正常还是异常 | 取样失败也出声，但不重复出声 |
| **交易闸门** | 这个信号开不开仓、开多少、风控过没过 | 同一根 K 线只判一次；判不了的留悬位等人 |
| **配件报价/比价** | 这件货这家店这个价，吃不吃 | 判过的不重判，价格变了自动翻面 |
| **定时任务** | 这个任务这一轮做过没有、结果是什么 | 重跑、并发、误触都不会重复劳动 |
| **日志/告警抑制** | 这条告警判过是噪音还是真事 | 判过的噪音不再叫第二遍 |

反面：**一次性的、答案随时会变的、不需要留痕的**别装。它是账本，不是缓存中间件，也不是数据库——你要查询、要排序、要联表，请另找一个正经数据库。



## 它解决什么 / The problem

AI 系统里最贵的不是算一次，是**把同一件事算两遍**。
同一个文件、同一条消息、同一个参数——判过一次就该记住。

The most expensive thing in an AI system isn't computing once, it's computing the same thing **twice**.
Ganglion 把判决写进账本：命中直接翻账（微秒级、零成本），没命中才真判。
**它不产生更好的判决，只让已有判决变得更便宜、可审计、可回放。**
（「谁判的、翻过几次、判错了怎么翻」这些属于上层账本，不在这一版；这一版只管「判过没」。）

## 用法 / Quick start

```python
from ganglion import Ganglion

def my_judge(content):
    # 你自己的判断逻辑，返回 (verdict, reason)
    return (1, "放行") if "病毒" not in content else (0, "拦截")

# 带记忆（mem 就是个 dict；内存 dict 进程一停就归零，要跨进程请传自己的持久化 dict）
g = Ganglion(mem={}, ttl=3600)
print(g.check("你好", processor=my_judge))     # → (1, '放行')              真判
print(g.check("你好", processor=my_judge))     # → (1, '[记忆:0s前] 放行')   翻账，不重判

# 不带记忆（纯反射）
g = Ganglion()
print(g.check("你好", processor=my_judge))     # → (1, '放行')              每次都真判
```

批量：

```python
from ganglion import Ganglion

def my_judge(content):
    return (1, "放行") if "病毒" not in content else (0, "拦截")

g = Ganglion(mem={}, ttl=3600)
print(g.scan(["a", "b", "c"], processor=my_judge))   # [(key, verdict, reason), ...]
```

健康探针（把「探活」也变成一个判决件）：

```python
from ganglion import Ganglion

probe = Ganglion.health_check("DB", lambda: (True, "通"))
print(probe.check(None))   # → (1, 'DB: 通')
```

## 三条硬设计 / Three hard rules

| 设计 | 为什么 |
|------|--------|
| **0 / 1 / None 三值** | 「没判出来」和「判出来是坏的」是两回事，合并会骗人 |
| **fail-open 不落账** | processor 抛异常 → 返回 `None` 且**不写记忆**。瞬时故障不会把坏判决固化一小时 |
| **`None` 也算结论** | processor 主动返回 `None`（「这次判不了」）会照常记账——它同样是一个结论，只是不是 0 |
| **骨里一个场景不放** | key 算法、三值语义、过期逻辑是结构；具体判什么，全交给你写的 processor |

**通用性来自「什么都不假设」**：只要求一个 `dict`、一个 `callable`。
不假设框架、不假设 I/O、不假设 ID、不假设生命周期。

> It assumes nothing: a dict and a callable. No framework, no I/O, no identity, no lifecycle.

## 什么时候**不**该用它 / When NOT to use it

这条比上面所有功能都重要——**装得下 ≠ 该装**。
免费正则能干的活它一样装得下；同一句邀请，拒绝十次的人才配装对那一次。

够格四条**全中**才装：

1. **判据纯靠内容**：同文必同判。判决若挂活变量（时间/账本/阈值/上下文历史），短 TTL 也别装——同文异判是它的本分。
2. **高频复判**：同一 content 反复进同一判据。装前先翻日志数复判段，拍脑袋不算数。
3. **判决可两值化**：verdict + reason 能冻结回放。
4. **有模型调用或一致性价值**：省 token，或统一同文判决（防判据忽松忽紧）。

**判死存档（真账回放，供你少走弯路）**

| 场景 | 命中率 | 判决 |
|------|--------|------|
| 缓存「含新鲜上下文的仲裁判决」 | 0.7% | 死。上下文每轮都变，key 每轮都动，无限 TTL 无救 |
| 同上，但只留消息做 key | 22.9%，旧判与新判一致率仅 89.8% | 死。第二意见被喂陈旧判决 = 拆台 |
| 消息流复读缓存（10min 窗） | 21%，tier 一致率仅 82% | 死。**复读 ≠ 同判** |

结论：**缓存救不了「进错门」的浪费，滤网才救得了。**
我们真正省下 97.9% 判决量的那一刀，是把不该进判决流的行挡在门外，不是给它加缓存。

## 接线三坑（我们踩过的，你也会踩）

1. **key 必须掺命名空间**。本体只哈希内容——多租户/多通道场景请自己把 `platform`、
   `tenant`、`channel` 编进 content 再传（如 `f"{platform}::{msg}"`）。
   否则 A 通道命中的缓存会漏进 B 通道。本体刻意不管这件事，**由宿主补**。
2. **记忆必须落盘**。挂在「每条消息起一个新进程」的钩子上时，进程内存活不过一条消息，
   不落盘等于白装。落盘前记得清掉过期与超量旧账。
3. **长 prompt 别直接塞**。key 取的是剥噪后的前 64 字符，模板头固定的长 prompt 会全员撞格，
   第一次判决灌给所有消息。要么自己 sha256 全文当 content 传，要么别装。

更多账本（fail-open 三层、回归台怎么搭、四个变体）见 [docs/KNOWLEDGE.md](docs/KNOWLEDGE.md)。

### 读账先 `audit()`，再喊"链断了"（2.1）

流水才是正本，快照只是压实产物；`hit` 这类行写进流水后，要等下一次带
`journal=` 的 `load`（或 `replay`）**重演**才进链。只拿快照对流水的人必然看见
「流水长了一行、链没长」——那是**未重演**，不是断链。两者混报过一次真实 issue
（2026-11-17，外部复现：三行代码调库即红）。所以读账口径定死：

```python
a = L.audit(path, journal=jp)   # 只读：不写行、不推进消费位
# a["unabsorbed_bytes"] > 0  → 只是还没人重演，load(journal=) 一下就对齐
# a["aligned"] is False 且重演后仍不齐 → 真缺口，值得开刀
# a["bad_lines"]         → 坏行另算一笔，不冒充上面两种
```

### 真并行：6 进程 × 80 步（round 56 量，**抓到 4 处根因**）

round 56 之前锁协议是「设计上互斥、测试上单进程」—— 所有并发用例都在一个进程里
靠 `threading` 模拟，跨进程的读-并-写从来没被真跑过。新工具
`tests/test_concurrency_mp.py`（Windows/spawn 三件套：`mp.get_context("spawn")`、
`if __name__ == "__main__"` 里 `mp.freeze_support()`、worker 是模块级函数；
固定 SEED 保证跨机复现）起 **6 个进程 × 80 次随机操作**（append / 墓碑 / 压实 / 时间线）
对着**同一个临时目录**的同一本账打，跑完逐条核 **7 条不变量**：

| # | 不变量 |
|---|---|
| ① | 链校验 `chain_break_at(L) is None`（节节连号、圈号 1..n 连续、第一圈是第一圈） |
| ② | 零丢失：append 过的 nid 集合 == 链上 nid 集合，一行不差 |
| ③ | 每一行（流水 / 快照 / 压实底 / 归档）逐行 `json.loads`，无半行无交错 |
| ④ | 锁零残留：`*.lock` 与 `.compact.lock` 一个不剩 |
| ⑤ | `recent(n)`（n∈{0,1,7,40}）与独立口径逐节一致 |
| ⑥ | 墓碑只可能来自"真 append 过且真扫过"的节（不许无中生有） |
| ⑦ | 扫成墓碑的节，终账上不许复活（**丢刀**） |

连跑 15 轮全绿（单轮 3–4s），全量 **285 passed**、conformance **45/45**、
unittest **51 OK**、property fuzz 6、scale 4 全绿。

**这轮的收获是 4 处根因**（改前都有 `.bak`，修的都是根因不是症状）：

| 根因 | 症状 | 刀口 |
|---|---|---|
| 所有进程共用一个 `path + ".tmp"` | 两份 JSON 按字节错位拼成坏本（`Extra data`、链上凭空两个第 1 圈）+ 先 replace 走的那个让别人 `FileNotFoundError` | 临时名改成每次写一个（pid + 纳秒），原子性一个字没变 |

### 崩溃注入：死在半路（round 57 量，**抓到 1 处根因**）

round 56 验的是「多进程**都活着**」；round 57 验的是另一半：进程**死在半路**
（崩溃 / 断电式硬杀，`os._exit` 注入钩子）之后，账还完不完好、锁还接不接得回来。
`tests/test_crash_recovery.py` 在 **6 个崩点**上硬杀子进程，每个点走同一段三步：
**杀在半路 → 母进程杀完再开 → 另起一个真进程（复活进程）在同一本账上接着干**。

| 崩点 | 死在哪 |
|---|---|
| `append_after_write` | `_write_line_unlocked` 返回之前（行已落盘、锁还在） |
| `append_mid_write` | write 中间（只有半截字节落盘 = 半行残尾） |
| `save_before_replace` | tmp 写完了、`os.replace` 还没换 |
| `save_after_replace` | 换完了、`_save_locked` 的收尾还没跑 |
| `compact_after_copy` | `shutil.copyfile` 拿到备份、正本还没截空 |
| `compact_after_truncate` | 正本已截空、第二次 `save` 还没进门 |

每个点核 **8 条**：① 链不断（`chain_break_at is None`）② 行数守恒 —— 崩点之前的
节数一节不许少，崩点那节 `landed=True` 必须在、`landed=False` 允许缺（任务书口径：
崩在写前 = 没写不算丢，崩在写中 = 那行允许缺但不许半行）③ 流水里没有 parse 不动的
行、`bad_lines=0` ④ 残留锁判得死（死 pid 当场接管；pid 被复用才走 `stale_after`，
测试把钟拨过期不真等 45 秒）⑤ `recent(n∈{0,1,7,40})` 与独立口径一致 ⑥ 复活进程
append + save + compact 在预算内跑完（**不许死锁**）⑦ 干完再开：一行半行都不剩、
行数仍守恒 ⑧ `*.lock` 一个不剩。另有两条钉子：`test_stale_lock_is_reaped_by_liveness_and_stale_after`
（活人的锁不抢 / mtime 过 `stale_after` 判死回收 / 死 pid 当场接管）与
`test_torn_tail_never_poisons_the_next_line`（半行残尾不许拖累后面那一行，单进程可复现）。

**抓到 1 处根因（改前 `ledger.py.bak_round57_20261107`），修根因不修症状**：
崩在 write 中间留下的半行残尾，下一次追加是 `open(path, "a")`，整行**粘在残尾后面** ——
读的人只在换行处切（`_absorb` 的 `rfind`），切出来的是「半行 + 新行」的杂交，
`json.loads` 当场失败：**坏一行、丢一行**（新写的那节整节没进链，`bad_lines` 当场 +1，
那节从此世界上发生过、账上没发生）。刀口 = `_heal_torn_tail()`：写者拿锁之后、追加

残尾往下写。代价实测（1 万行 ×2 轮同机同尺）：append **7.78–7.89s → 8.09–8.33s**
（0.78 → 0.82 ms/行，约 **+5%**，换的是崩在写中不再拖累后面每一行）。
另外 5 个崩点（append 写完、save 的 replace 前后、compact 的拷底与截空）**账与锁
本来就是好的**：一条不变量没破、锁全走死 pid 当场接管 —— 按任务书条款只交测量，不动刀。

### IO 错误注入：盘满 / 建不了锁（round 58 量，**抓到 2 处根因**）

| 注入点 | 打在哪 | 三问实测 |
|---|---|---|
| `append_enospc` | 写流水 `open(jp, "a")` → ENOSPC | ① `OSError[errno=28]` ✓ ② 流水一字节没动、失败那节**不在盘上** ✓ ③ 恢复 ✓ |

| 根因 | 症状 | 刀口 |
|---|---|---|
| `compact()` 把拷底失败**吞成 `return False`** | 那个值在契约里是「有人在压，这次让路」—— 盘满被说成别人在干活：调用方看不出原因，`stat` 里只有一笔混在一起的 `compact_skipped`；半份底（没登记过，`_prune_backups` 永远不删、`load` 还会去读）留在盘上 | `except OSError` 改成带 errno 如实抛（`压实拷底失败（No space left on device）`）+ 收走自己刚起名的半份底 + 计 `stat["compact_io_failed"]` |

不动刀的两个点（按任务书条款只交测量）：`append_enospc`、`save_replace_enospc`
**本来就诚实** —— 真抛、`errno=28`、盘一个字节没动、锁与 tmp 零残留，一条不变量没破。
另有 1 条钉子 `test_lock_tells_cant_create_apart_from_dont_own`（锁文件在 = 让路、
锁文件不在 = 如实抛、撤掉故障同一把锁照旧拿得到），把刀口两侧都钉死。

连跑 3 轮全绿（单轮 0.96–1.01s，单点 ≤0.8s，远在 30s 线内），全量 **298 passed**、

### 损坏与恶意输入：八类坏文件三问（round 60 量，**抓到 6 处根因**）

round 56/57/58/59 把正常输入、真并行、崩在半路、盘满、长跑都验完了；这一份补最后一块
空白：**账本文件是外部可触的** —— 谁塞个坏文件进来，都不能把它打死、挂死、撑爆，
也不能让它把坏数据吞了假装读全了。新写 `tests/test_malformed_input.py`
（corpus **8 类** + 1 条 corpus 计数 = **9 条**；固定种子 `SEED = 20261107`，全程 pytest
临时目录，真实账一个字节不碰）。**每一类都在子进程里跑**：父进程掐表 10 秒（挂了 / 超了
当场 kill 判红）、子进程自采 RSS 峰值、400 MB 线（撑爆即红）——
「不许挂死、不许撑爆」是量出来的，不是读代码读出来的。

| 类 | 打什么 | 三问实测（先测后修） |
|---|---|---|
| ① 截断的 JSON 行 | 半行 / 空行 / 纯空格行混杂 + 末尾没换行的残尾 | **没抓到东西**：2 条带换行的坏行进 `bad_lines`、原账 3 节一节不少；残尾由写者自愈（round 57 那把刀），append → 重读 4 节、链不断 |
| ② 二进制垃圾 | 固定种子 4096+8 字节随机字节（含 `\x00`/`\xff`）+ 2048 字节坏压实底 | **没抓到东西**：流水两坨与坏底都进 `bad_lines`（≥3），原账 3 节不动 |
| ③ 超长单行 | ≥10 MB 一行（合法的与截断的各一条，流水 10 487 089 字节） | **没抓到东西**：1.12s 吃完、RSS 峰值 85 MB（线 400）；截断那条是残尾，append 自愈后新行落稳 |
| ④ 深嵌套 10⁵ 层 | 流水一条 + 快照一份 | **红 → 收刀**：`RecursionError: Stack overflow … while decoding` 冒到 `load` 外面（流水、快照两处都打死） |
| ⑤ 非法 UTF-8 字节 | 流水两行乱码（一行 hit、一行 node）+ 快照乱码 | **红 → 收刀**：`decode("utf-8","replace")` 把坏字节「修好」成一节真账进链（nid 变替换字符、`bad_lines=0`）；`replay()` 整份 strict 一抛 `UnicodeDecodeError`（两个读入口两把尺）；快照拒绝不点名文件 |
| ⑥ 字段类型炸弹 | `round` 是对象/数组、`verdict="对"`、整行 `123`、`t=123`、快照容器与字段类型不对 | **红 → 收刀**：`123` 那行 `AttributeError: 'int' object has no attribute 'get'` 冒到 `load` 外面；`{"t":123}` 认不出的类型被记成「已重演」（假绿）；快照 `'list' object has no attribute 'items'` 不点名文件、字段炸弹**静默收下** |
| ⑦ 重复 nid 的两节 | 同一节写两遍（内容一样 / 同号不同内容各一对） | **红 → 收刀**：同号不同内容的两节都进了链，链上两节占同一个号，认人索引只指得到一节 |
| ⑧ 流水与底对不上 | `_journal_upto` 越界 + 底 6 节而流水是空的 | **没抓到东西**：底比流水新照样读得出 5 / 6 节，链不断、append 照常 |

**6 处根因，全在读这一侧，各修各的根（`ledger.py.bak_round60_20261107` 先行）**：

1. **深嵌套**：`_replay_lines` 接住 `RecursionError` 记坏行（一行深嵌套 = 这一行的事，

   换成**点名文件**的明确拒绝。

   一律进 `bad_lines`（以前 `rec.get("t")` 当场 AttributeError）。
3. **认不出的类型**：`_replay_one` 没有这一支就抛 —— 认不出来是坏行，不许算成「已重演」。
4. **非法 UTF-8**：新写 `_decode_lines` —— 整段解得动走快路（与以前同速），解不动

   `_absorb` / `_absorb_backup` / `replay()` 三个读入口同一条路。

6. **同号两节**：`_replay_node` 把「认身份」提到圈号判断之前 —— `_same_node` 的口径本来就是

**坏本不自己绕开**：快照可能比流水新（压实会截空流水），所以底坏了**不许**自动降级成
「只读流水」—— 那等于把底里独有的节静默丢了。拒绝 + 点名 + 留全原文件，是这一条的全部口径。

### 文件损坏 fuzz：随机字节打在真账上（round 61 量，**抓到 2 处根因**）

round 60 的损坏语料是 8 个**手写**样本；round 61 把「损坏」变成**随机生成的规模化模糊** ——
`tests/test_file_fuzz.py`（**19 条** = 12 个固定种子 + 手法覆盖 1 + 根因钉子 3 +
覆盖度 1 + 护栏自检 1 + 全文件掐表 1）。每种子先用正常操作攒一本小真账
（流水 + 快照 + 一份压实底，6 节），再随机选 **1–3 种手法**打在**流水和快照上各来一遍**：

| 手法 | 干什么 |
|---|---|
| `flip` | 随机字节翻转（1–6 处，各异或一个随机位） |
| `truncate` | 随机位置截断（只留前缀） |
| `move` | 随机切一段挪到别处（段长 ≤ 1/4） |
| `splice` | 头尾拼接两份文件（拿第二本真账的同名文件来拼） |
| `drop` | 抽掉中间若干字节（段长 ≤ 1/3） |

五条不变量（任一违反即红）：**① 不打死**（未捕获的 RecursionError / UnicodeDecodeError /
AttributeError / JSONDecodeError 一律收进「带原因、点名文件的拒绝」或坏行）、
**② 不挂死**（单种子 10s 掐表，子进程 kill）、**③ 不假绿**（`bad_lines` 盖得住独立数出来的
「确实解不动的行」、拒绝点名文件、行数只少不多、少的能说出少哪）、
**④ 处理后同目录还能用**（append → 重读：链校验过、行数守恒、recent 对得上）、
**⑤ 原文件一字节不动**（测试自己才是破坏者）。

**先测后修：2 处根因收刀，全在读这一侧（`ledger.py.bak_round61_20261107` 先行）**：

1. **流水侧**：`_replay_node` 不验「节上署的地址 = 记它的地址」—— 随机字节打在 `key`
   字段上，这一行照样 parse 得动、照样长得像一节账，收下就等于把别人的账挂到这个地址
   下面，载入出来的链当场「节和地址对不上」。现在这一行抛出去**记一笔坏行**：
   一条坏数据只坏它自己那一行，不许把链带坏。
2. **快照侧**：`_check_snapshot_shape` 只验类型、不验链 —— 地址或圈号被改了，JSON 照样
   合法、照样收，载入出来的账链当场是坏的（圈号 `None` / 断号 / 节和地址对不上）。
   现在链的两条硬规矩（节上的 key = 地址、圈号 1..n 连号）也进形状尺：**明确拒绝 +
   点名文件与哪一格 + 原文件一个字节不动**，挪开之后同目录照常干活。

**护栏自检**（防尺子睡着）：八把尺各喂一份**故意打坏**的输入（没接住的异常、超线的耗时、
被改的字节、变多的行数、盖不住的坏行数、说不出来的缺额、不守恒的行数、断了的链）——
每把都真响；再各喂一份干净输入，确认不会永远红。

实测（`python -m pytest -q -s tests/test_file_fuzz.py` → **19 passed in 6.23s**）：
12 个种子子进程 0.04–0.06s（线 10s）、墙钟 0.44–0.55s，全文件 **6.0s**（线 120s）；
覆盖面：快照被拒 9 个 / 收下 3 个、流水里有坏行 8 个 / 一行坏行没有 4 个、五种手法各 2–5 次。
**改前**把同一份测试连同改前的 `ledger.py` 拷进临时仓复跑：**8 failed, 11 passed**
（两颗钉子 + 种子 8/15/56/79 + 覆盖度），改后全绿。另用交付版 `run_seed` 大面复扫：
种子 1–300 × 2 遍（**600 次**不同 uuid/时间戳的损坏）+ 定案 12 种子 × 20 遍（**240 次**）= **0 红**。
全量 **328 passed**、conformance **45/45**、unittest **51 OK**、
fuzz 6 + mp 3 + crash 8 + io 5 + longrun 2 + malformed 9 + file fuzz 19 = **52 passed**。

### 规模：1 万行内健康（round 53 量、round 54 收刀）

`python tools/scale_stress.py` 合成大账跑 **append → 墓碑 → 压实 ×2 → 时间线 → 落盘重读** 全链路，
三种 key 分布（`uniform` 1 地址 1 节 / `hot` 50 地址吃掉全部行 / `skew` zipf 长尾）× 1k/5k/10k，
另加 uniform 20k/50k、hot/skew 20k 找拐点。跑完三条不变量都真（链校验 `break_at=None`、
行数守恒、`recent` 与独立口径逐节一致），**1 万行 ×3 分布全链路 round 53 是 9.7–34.3s，
round 54 修完收到 9.7–9.9s**（现在贵的是 append 的锁与回读，不是压实）。

| 量的什么 | 实测 |
|---|---|
| `append`（短命进程那条路，带锁 + 写后回读） | **1.0–1.3k 行/s（≈1 ms/行）**，uniform 1k 0.83s → 50k 48.42s，**线性到 5 万行** |
| `record`（常驻进程那条路，只写内存） | 1 万行 **0.05–0.08s**（≈15 万行/s）—— 落盘那一步贵在锁与回读，不贵在记账 |
| 墓碑 `sweep_ttl`（1 万行，立 3000 节） | **0.05–0.08s** |
| 时间线 `recent`（1 万行全窗） | **0.01–0.02s**；5 万行 0.05s |
| 落盘重读 `load`（快照 + 流水重演） | 1 万行 **0.07–0.10s**；5 万行 0.68s |
| 内存 | 1 万行快照 **3.3–3.6 MB**（≈350 B/节）、Python 层峰值 **24–26 MB**（≈2.5 KB/节）；5 万行快照 17.79 MB |

### append 拆项：六块平分、没有大头（round 55 量，**没动刀**）

round 54 说"贵的是 append 的锁与回读"，round 55 把 append 单环节拆开看各占多少毫秒。
工具是新的 `python tools/append_profile.py`（**账本代码一行没改**：给 ledger 的 `open / os /
time / json` 打代理、给 `_lock_own / _drop_lock / _lock / record` 包一层计时；
**自检**：插桩前后跑出来的流水逐行一致 —— t/key/verdict/round/reason/ctx_fp，nid 是 uuid
不比 —— 不一致这把尺就不作数）。1 万行 × 三种分布、每档两轮取开销更小那轮：

| 环节 | uniform | hot | skew | 占比（三分布） |
|---|---|---|---|---|
| 拿锁 `_lock_own`（O_EXCL 建锁 + 写 pid + 判锁） | 0.18 ms | 0.20 ms | 0.17 ms | **20.7–21.2%** |
| 写流水（open 'a' + write + tell + 关文件） | 0.13 ms | 0.15 ms | 0.13 ms | 15.4–15.5% |
| 落稳 flush（**显式 fsync 0 次**，只有 flush 到操作系统） | 0.04 ms | 0.04 ms | 0.04 ms | 4.4–4.5% |
| 回读重放（open 'rb' + seek + read + fstat/stat 比代 + 关文件） | 0.16 ms | 0.17 ms | 0.16 ms | 18.2–18.7% |
| 释放锁（close(fd) + `_drop_lock` unlink） | 0.17 ms | 0.19 ms | 0.17 ms | 20.2–20.4% |
| └ 记账 `record`（内存链 + uuid4） | 0.02 ms | 0.02 ms | 0.02 ms | 2.4–2.5% |
| └ 序列化 `json.dumps` | 0.03 ms | 0.03 ms | 0.03 ms | 3.1–3.2% |
| └ 流水大小 `getsize` | 0.06 ms | 0.07 ms | 0.06 ms | 6.9–7.0% |
| └ 残差（进程内线程锁 / 参数护栏 / 循环本身） | 0.07 ms | 0.08 ms | 0.07 ms | 7.8–7.9% |
| **合计** | **0.85 ms/行** | **0.96 ms/行** | **0.84 ms/行** | 100% |

同尺基线（不插桩）1 万行：**7.68 / 7.69 / 7.59 s ≈ 1280–1310 行/s**，和上表
"1.0–1.3k 行/s"对得上；插桩开销 10.7–24.8%，占比取开销更小那一轮。
交叉验证：`cProfile` 独立跑同一负载，`_lock_own` 21.1%、`_drop_lock`+close 20.1%、
`_write_line_unlocked` 41%（= 写 15.5 + 落稳 4.5 + 回读 18.6 + 关文件）与上表对得上。

**结论：没有 ≥40% 的那块 —— 按规矩只交测量表，不动刀。** 最大单块是拿锁 21%，
六块 15–21% 均匀，不是单点瓶颈；唯一过 40% 的读法是"锁往返合计"（拿 21% + 放 20% = 41%），
但要降它就得动锁协议，而互斥保证排在速度前面、收益上限也就 20%，不值当。

**规模拐点在第一次压实**（快照还不存在时的那次，要整本重演流水）：浅链线性 ——
uniform 1 万行 1.0s、5 万行 6.1s；深链**二次增长** —— hot 1 万行 10.1s → 2 万行 36.7s、
skew 1 万行 17.0s → 2 万行 61.8s（2× 行数 → ~4× 耗时）。根因是 `append` 写的行**不带圈号**
（`round = None` —— 圈号属于重演出来的位置，不属于写的那一方），重演时只能逐节按内容认人：
**每行扫一遍本地址的链，还给每个候选节现造两个临时字典**，链越深越贵。

**round 54 修的就是这个根子**（修法一句话：节点一进链就把 `nid → 下标` 登记成**认人索引**，
重演时先查表 O(1) 认人、查不到才退回逐节比内容 —— 账本格式语义与老账兼容**一个字没改**，
没 `nid` 的历史行照旧逐节比内容）。同一台机器、同一把尺（`--sizes 10000,20000 --dist hot,skew`）
前后对照，修后连跑两次取区间（两次都是改完的最终代码）：

| 分布 | 行数 | 首压实（修前 → 修后） | 第二次压实（修前 → 修后） |
|---|---|---|---|
| hot | 1 万 | 9.35s → **0.88–1.28s** | 1.26s → **0.65–0.67s** |
| hot | 2 万 | 34.95s → **1.82–1.89s** | 3.80s → **1.83–1.85s** |
| skew | 1 万 | 22.11s → **0.97–1.20s** | 2.22s → **0.66–0.78s** |
| skew | 2 万 | 75.28s → **1.83–2.20s** | 6.54s → **1.39–1.69s** |

**2× 行数的增幅：首压实 hot 3.7× → 1.5–2.1×、skew 3.4× → 1.5–2.3× —— 二次增长没了，
回到线上下**；第二次压实 3.0× / 2.9× → 2.1–2.7×，绝对值从 3.80s / 6.54s 掉到 1.8s / 1.5s 上下。
把压实拆开逐项量（`save` / `_absorb` / `load` / `_merge_from`）：**每一项 2× 行数都是 ≈2× 耗时**，
没有哪一步还在平方 —— 剩下的是 JSON 序列化与磁盘 IO 的常数，不是复杂度。
round 53 那次量的是 10.1/36.7s、17.0/61.8s —— 同一根子、不同时刻的机器，量级一致，旧数不替换。
所以：**1 万行内健康**（三种分布全绿），**超过 1 万行先看链深**这条旧提醒**已经不成立** ——
hot/skew 2 万行的首压实 1.8–2.2s，压实不再是全链路里最贵的一步（贵的是 append 的锁与回读）。

> 量内存别开着 `tracemalloc` 计时：它把每一次分配都记一笔，实测把 1 万行的首压实
> 从 7.4s 拖到 53s —— 拿它计时得出的"拐点"是测量工具自己的拐点。工具默认关掉，
> 要 Python 层峰值加 `--trace-mem`（只作内存读数）。
> round 53 在这儿量出的深链二次增长，round 54 的修法一句话：把"逐节比内容"换成"查认人索引"
> （`地址 → {nid: 下标}`，懒建、进链即登记；老账没身份号，照旧比内容）—— 数见上表。

## V2 · 账本 / The Ledger

V1 的骨不动。V2 是长在它外面的一本账：**判过的每一次都留一节**，能查、能追、能验。

V1 记的是 `content → verdict` 两个格子，后判覆盖前判——于是「它变过没有」这个问题，在 V1 里根本问不出来。
V2 把被覆盖掉的东西接住：一条离散的判决链 + 三根连续的轴（值多少 / 谁翻过 / 第几回）。

**出去的永远是三个值当中的一个**：

| 值 | 是什么 |
|---|---|
| `1` / `0` | 判是 / 判否。塌缩了，落一节账 |
| `悬位`（`Pending`） | **正在进行中**，不是"没有答案"。判决栏空着，另记三样：差什么、第几圈、试过几次 |

空有三种质地，三个方向：缺料（该补料）、缺硬证据（该升档或交人）、配不上（**这不是空，是该重算**）。
混了第三种，系统会永远在往上交——看着谨慎，实际重算一次也没发生。

| | 是什么 |
|---|---|
| 规范 | [docs/LEDGER.md](docs/LEDGER.md) —— **不含任何测试数字**：方法给你，数自己量 |
| 通用件 | [ledger.py](ledger.py) —— 三值 + 六面 + 借账留痕 + 署名 + 落盘。**不给默认值**：不给 `writer` 就不许落账，不给 `ttl` 就不许借账，不填 `deliver` 悬位就不往外交 |
| 示例 | [examples/ledger_minimal.py](examples/ledger_minimal.py) —— 七段，纯 stdlib，跑一遍就懂结构 |

```python
from ledger import Ledger, LedgerGanglion, addr
import os

BOOK = "book.jsonl"
if os.path.exists(BOOK):
    os.remove(BOOK)                # 演示专用：先给一份干净的账（真接线不删账）

content = "这台车合规吗"            # 你手上那句话
my_fn = lambda c: (1, "手续齐")     # 你的判断：返回 (判决, 理由)
my_fp = lambda *a: "fp|A"           # 你的情形指纹

L = Ledger(writer="eyes", ttl=3600, deliver=print)   # 谁在写 / 你的窗 / 你的交接人
g = LedgerGanglion(L, journal=BOOK)                  # 它会借账，所以借票得有地方落
v, why = g.check(content, processor=my_fn, ctx_fp=my_fp(content))
print(v, why)   # → 1 手续齐 —— v 是 1 / 0 / Pending，Pending 时判决栏空着，账上不多一格

L.record(addr("这台车合规吗"), 1, "手续齐", ctx_fp="fp|A")   # addr() 是公开的地址函数
n = L.probe(addr("这台车合规吗"), "fp|A", journal=BOOK)      # 借这一下也落一行
print(n["verdict"], n["ctx_fp"], n["hits"] >= 1)   # → 1 fp|A True（圈号与命中数在 n["round"] / n["hits"] 里）
# journal 必填：真的不要落票才写 journal=False（只许单进程）
```

> 缓存问「省了多少」，账本问「凭什么」。
> 两边的人都只做了一半，中间那条缝一直空着。

## 两种写法：只记不借 / 只记跃迁

真跑起来（每分钟一次的写延迟哨兵）才发现，账本有两种完全不同的用法：

**只记不借** —— `Ledger(writer="…")` 不传 `ttl`，借账直接抛 `LedgerBlocked`。
不是防呆，是一种正经模式：你只要"写过什么"这份凭据，不打算拿旧判决去抄。

```python
from ledger import Ledger, addr
import os

JOURNAL = "led.jsonl"
if os.path.exists(JOURNAL):
    os.remove(JOURNAL)             # 演示专用：先给一份干净的账（真接线不删账）

L = Ledger(writer="disk-sentinel")             # 明确：只记，不借
key, ctx = addr("写延迟 峰值 0.03s"), "fp|probe"
L.append(JOURNAL, key, 1, "峰值 0.03s", ctx)   # 只追一行，不读全本
print(open(JOURNAL, encoding="utf-8").read().strip())   # 就这一行
```

**只记跃迁** —— 状态没变就不记。这是账不爆的关键：
一个每分钟跑一次的器官，一天 1440 次判决，全记就是 1440 节/天；只记跃迁，一天可能零节。

```python
from ledger import Ledger, addr
import os

JOURNAL = "sentinel.jsonl"
if os.path.exists(JOURNAL):
    os.remove(JOURNAL)             # 演示专用：先给一份干净的账（真接线不删账）
key, ctx = addr("盘 /data 这次痛不痛"), "fp|disk"
L = Ledger(writer="disk-sentinel")             # 状态在调用方手上，账本只管记
st = {}

rounds = [(True, "峰值 0.031s > 0.02s"),    # 疼了
          (True, "峰值 0.031s > 0.02s"),    # 还疼（不变 → 不记）
          (False, "回到 0.005s")]           # 恢复了：对面显形
for hit, reason in rounds:
    if hit and not st.get("book_pain"):        # 不疼 → 疼：这一下才配记
        L.append(JOURNAL, key, 1, reason, ctx); st["book_pain"] = True
    if not hit and st.get("book_pain"):        # 疼 → 不疼：对面显形
        L.append(JOURNAL, key, 0, reason, ctx); st["book_pain"] = False

lines = [x for x in open(JOURNAL, encoding="utf-8").read().splitlines() if x]
print(len(rounds), "轮判决 →", len(lines), "节账")   # → 3 轮判决 → 2 节账
```

**按判据记** —— 该不该记，交给判据，账本只在源头拦。跟「只记跃迁」是两回事：
跃迁管的是"变没变"，判据管的是"记了划不划算"（期望收益 = 重放概率 × 重算成本 − 写入成本）。

```python
import admission
from ledger import Ledger, addr

key, ctx = addr("树搜索节点 扩展 A"), "fp|tree"

L = Ledger(writer="w", ttl=3600, admit=admission.gate("tree_search"))   # 一行接上
print(L.record(key, 1, "算出来的", ctx))   # 期望收益 > 0 → 落账，返回这一节

L2 = Ledger(writer="w", ttl=3600, admit=admission.gate(replay=0.001, cost=1.0))
print(L2.record(key, 1, "算出来的", ctx))   # 判据说不值得记 → 返回 None，不进链、不写流水
print(L2.stat["admitted_out"])              # 拦下的节不进链不写流水，只在账面上计一笔
```

判据在 [admission.py](admission.py)（判的和记的是两条链：判据写错，账本不该跟着错）。
不传 `admit` = 不拦、全记 —— 账本不知道你的重放概率，那是调用方的事。
拦下的节不进链、不写流水、也不塌缩悬位，只在 `stat["admitted_out"]` 计一笔，账面上看得见。
**收口（`resolve`）、订正（`revisit`）、重演（`load` 回放）不过闸** —— 判据拦的是新算出来的批量判断，
这三样是"必须留痕的那类事"，拦掉就是抹账。

短命进程（一分钟一次那种）用 `append` 只写流水；读的一方 `Ledger.load(path)` 一次回放 —— **它是类方法**，返回一本新账；`L2.load(p)` 不会把数据装进 `L2`。读一个不存在的路径会报 `FileNotFoundError`（以前会静默交回一本 0 节空账，路径打错和「还没写过」长得一模一样）；真要读新账请 `empty_ok=True`。
流水写到一半断电也不会被瞎猜——半行当没写过。

## Z 轴：五件

时间这一维落成五件，前四件管怎么走，第五件管怎么死：

| 件 | 一句话 |
|---|---|
| `record(ttl=)` | 每节自带一个钟，不是整本账共用一个 |
| `decide_by` | 悬位有收口期限，到点收不了就留痕"到点无据" |
| `min_age` | 刚判完又问一遍的不许借——那是抖动，不是结论 |
| `revisit(key, 圈)` | 拿今天的判据重演旧圈，旧节不许改，翻面能分出"判据变了 / 情况变了" |
| `prune()` | 判过、没人翻、不在翻转序列上的平淡节褪成梗概（判决、圈号留住）；墓碑只由 `sweep_ttl()` 立 |

`ttl` 为什么必须记在节上：一本账里可以同时住着两分钟一圈的器官和一年一圈的保险。给一个统一默认值，**等于拿肠子的节奏管神经元**。

## 起念与结算：两件刚长出来的（2026-11-06）

**出站口（起念）** —— 被问才答、到点就响之外的第三种开口：**账内状态自己叫醒**。

| 圈况 | 素名 | 什么时候响 |
|---|---|---|
| 翻了 | `flip` | 相邻两圈判决不同（`flips()` 现成） |
| 卡了 | `stuck` | 转满 3 圈仍无进展：悬位没塌缩 / 判决不更新（两档） |
| 通了 | `converged` | 这一节在窗内**且确实被翻过**：答案问就有 |

- `L.stuck(key)` 答「**这条地址卡了多久没动**」（`idle` 秒）—— **两档**，判据都只数圈、不看墙钟（快慢线各转各的圈）：
  - 第一档 `kind=悬位没塌缩`：悬着的位置被问满 3 圈还没塌缩。「动」= 落下新的一节 / 悬位塌缩，**再问一次不算动**（那是原地转圈）。
  - 第二档 `kind=判决不更新`：链上落满 3 圈真实判决、**判决从头到尾一个样** —— 圈转满了，判决栏一个字没动过。翻过面的不算（更新过就是有过进展），墓碑不占圈，第一档报过的地址不重报（一档管悬着的、二档管判决链的，不重不漏）。
- 两档都只报事实，**不替你算「值不值得开口」**；第二档尤其别当「这条判据没救了」的判决 —— 值不值得叫醒是外面那道期望收益闸的事。阈值 3 圈是三件套空格（默认 + 说明 + 可调）。
- `L.signals(journal=…)` 把三圈况落成一行行日志。`journal` 必填（同 `probe` / `resolve`），要落账必须署名。
- 信号是**日志不是账**：不进链、不改判决；只报事实，**不替你算叫不叫醒** —— 值不值得开口是外面那道期望收益闸的事。

**信号与闸的边界（写死，别把信号直接接成调用）** —— 谁管什么，一张表说完：

| 谁 | 管什么 | 不管什么 |
|---|---|---|
| `L.signals()` / `L.stuck()` | 什么时候**可能**值得开口（翻了 / 卡了 / 通了，事实） | 不算划不划算，不给动作 |
| `admission` 期望收益闸 | 这一**笔记不记**（接在 `Ledger(admit=)` 上） | 不读信号、不知道响过没 |
| 「叫不叫醒」 | 调用方拿信号**现算**的第三处，同一把尺 | 账本不替你算，也不提供叫醒动作 |

- 同一把尺：**期望收益 = 重放概率 × 重算成本 − 写入/叫醒成本，`≤ 0` 不记不叫**（当没响过）。
  信号侧把「重放概率」读成「这条之后真会有人来问的概率」，「写入成本」读成「叫醒成本」，式子一个字不改。
- 四条禁令：① 信号不进链、不改判决、不塌悬位 —— 拿到信号不许直接 `record()` 当结论；② 事件字段里没有 `action` / `gain`，**读不出「该叫了」**，别去事件里找批准；③ 叫醒必须过期望收益，`≤ 0` 当没响过，`converged` 也一样（「问就有」≠「值得问」）；④ 两条链互不 import（双螺旋）—— `admission` 不读信号、`signals` 不读判据，谁写错另一侧不跟着错。
- 钉住它：体检「信号不越权」（45 项之一）+ `tests/test_signal_boundary.py`。

**结算（两行）** —— 预计一笔、实际一笔，差值回流。

- `L.expect(key, 数字, journal=)`：判决那一刻的「我预计…」（ts 是当下，**不许事后回头改**）。
- `L.actual(key, 数字, journal=)`：事后由现实回填的「实际…」（ts 是后来；什么算实际由使用者定）。
- `L.gap(key)`：差值 = 预计 − 实际。**缺一边如实报 `None` —— 缺笔不是 0 分。**
- 差值怎么折成 `value_score`：可选工具层给了一个带说明的默认口径 `tools/gap_value.py` —— `score = scale / (scale + |gap|)`（正好猜中 1.0、差满 `scale` 腰斩、缺笔原样传 `None`、永不等于 0）。**多笔按 `ctx_fp` 合成一个数**也给了示例 `aggregate(buckets)`，照条件概率表两步走：情形内逐笔折分再等权平均（先折后平均 —— 高估低估不许在差值层互相抵消），情形间按笔数占比边缘化 `value = Σ P(fp) × (score|fp)`；`None` 不投票（缺笔不进笔数），一笔有效数据都没有就返回 `None`。要看中间那张条件表用 `by_context(...)`。**多笔回填按什么顺序进聚合**（round 49）的答案是：**顺序不进聚合**（求和可交换，谁先谁后一个样），进聚合的是**时间衰减权重** `w = 0.5 ** (age / half_life)` —— 新回填说话重，默认半衰期一周（`half_life = 604800` 秒），`age` 与 `half_life` 同单位（按圈数衰减就两个都传圈数）。情形内平均变 `Σ w·score / Σ w`，情形间 `P(fp)` 变权重和占比；笔上**没给 `age` → `w = 1.0`**（不编时间、不猜年龄，等权 = round 48 那版行为），给了 `age` 的缺笔照旧不投票。**三件套空格**：衰不衰、半衰期多长、按频次/重要性加权，都在调用方手里。**不硬绑主链**：工具不 import 账本、不回填，回不回填、回填哪一圈、权重怎么改都还是使用者的空格。整条线（多笔回填 → 衰减加权 → 情形聚合，含落盘往返与缺笔护栏）串起来的用例在 `tests/test_decay_aggregate_line.py`。

两件都零业务词、都要署名、都要 `journal`；两笔不进判决链，流水是正本（全量），快照带最新一对。

## 时间线：最近 N 节（`L.recent(n)`，round 52）

六个取用面都是**按地址**取的（`by_value(key)`、`six_port(key)`…）。要看「整本账最近发生了什么」，用 `L.recent(n)` —— 跨地址的一条时间线，**只读：不改链、不动统计、不落一个字节**。

三件口径写死（Known gaps 里「没有时间线查询」那一行的关法：三件定不清就不准开这个口）：

| 口径 | 定成什么 |
|---|---|
| **查什么** | 所有地址上的每一节，节点自带 `key`，穿成一条时间线 |
| **按什么排** | 按**节自带的钟** `ts` 降序 —— 跨地址没有共同的链序（两个地址各转各的圈，圈号 1 不比圈号 3 旧）；同一个 `ts` 按圈号降序、再按地址升序，次序是确定的，不看字典的迭代顺序 |
| **边界给谁** | **墓碑不算**（「忘」那一档判决栏已空，它不在时间线上）；**褪色节算**（`prune` 褪成梗概的，判决和圈号还留着）；n 从最新往回数，不够就全给，`n <= 0` 给 `[]`；没有钟的节排不了（别拿 0 当钟） |

```python
from ledger import Ledger, addr

L = Ledger(writer="w", ttl=None, now=lambda: 0.0)
L.record(addr("甲"), 1, "甲第一圈", "fp", ts=100.0, ttl=60)
L.record(addr("乙"), 0, "乙第一圈", "fp", ts=300.0, ttl=60)
L.record(addr("甲"), 0, "甲第二圈", "fp", ts=200.0, ttl=60)

print([(n["ts"], n["round"]) for n in L.recent(2)])   # → [(300.0, 1), (200.0, 2)]
print(L.recent(0))                                    # → []（n <= 0 空手，不报错）
```

面还是六个 —— `recent` 不是第七个面，是把六个面按时间穿起来换个姿势看（速查表在 [docs/LEDGER.md §13.2](docs/LEDGER.md)）。钉住它的测试：`tests/test_recent.py`（7 条）。
